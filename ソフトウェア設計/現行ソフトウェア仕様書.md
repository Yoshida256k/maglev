## 1. 現行システムの位置づけ

現行は **「試験用のインバーター信号源」** の段階。要求仕様のうち、PWM 生成・SD 制御・非常停止・単相／オーディオは実装済み。位置検出・区間切り替え・V/f 制限・ホール同期運転は未実装。

```
 ┌──────────── 操作アプリ（PWA, web/）────────────┐
 │ PC: Chrome/Edge + Web Serial                    │
 │ Android: Chrome + WebUSB（CDC-ACM 直接、DTR ON） │
 │  ・インバーター操作カード（運転/直流励磁/音声）  │
 │  ・オシロ風表示（ファームと同じ計算の模擬波形） │
 └───────────────┬────────────────────────────────┘
                 │ USB CDC（テキスト 1 行 1 コマンド ＋ 音声バイナリフレーム）
 ┌───────────────┴───── YD-RP2040（200 MHz）──────┐
 │ main.cpp : 受信・コマンド解析・CH1/CH2・LED・WDT│
 │ inverter.cpp : 状態機械・PWM 割り込み・音声再生 │
 └──┬──────┬──────┬──────┬──────────┬─────────────┘
   GP4    GP6    GP8    GP10       GP11
   U IN   V IN   W IN   /SD(共通)  非常停止SW
    └──────┴──────┴──→ IR2302 ×3 → IGBT ハーフブリッジ ×3
```

| GPIO | 機能 | 設定 |

### 3.3 処理構成と周期

| 処理 | 起動 | 周期 | 内容 |
|---|---|---|---|
| PWM 割り込み `invIsr()` | U スライスの wrap 割り込み（最高優先度、RAM 配置） | キャリア 1 周期 | 位相を進め、テーブルを引き、3 脚の比較値を書く。音声は 1 サンプル補間 |
| 非常停止割り込み `estopIsr()` | GP11 立ち下がり | エッジごと | `hardStop()`（SD=Low → PWM 停止） |
| 周期処理 `invPoll()` | `loop()` から毎回呼び、前回から 1 ms 以上たっていれば実行 | 約 1 kHz | m・f のランプ、プリチャージ完了、直流励磁の角度移動とタイムアウト、音声の残量報告と終了判定、非常停止の保持確認 |
| 受信 `readSerial()` | `loop()` | 毎回 | テキスト行と音声フレームの分離、コマンド実行 |
| USB 切断監視 | `loop()` | 毎回 | DTR が 1→0 で `invOnHostDisconnect()` |
| ウォッチドッグ | `loop()` の最後で `wdt_reset()` | 500 ms | 止まったらリセット |

### 3.4 PWM 生成

**キャリア**（`applyCarrier()`）

```
top1  = round(200 MHz / (2 × fc_set))      // 三角波 1 周期のカウント数 (= TOP+1)
fcAct = 200 MHz / (2 × top1)               // 実際のキャリア周波数
dmin  = max(DUTY_MIN = 2 %, T_LOW_MIN (1 µs) × fcAct)
ccMin = ceil(dmin × top1)、ccMax = top1 − ccMin
```

| fc 設定 | top1（分解能） | dmin | クリップしない m の上限 1−2·dmin |
|---|---|---|---|
| 10 kHz | 10000（約 13.3 bit） | 2 % | 0.96 |
| 20 kHz | 5000（約 12.3 bit） | 2 % | 0.96 |
| 50 kHz | 2000（約 11 bit） | 5 % | 0.90 |
| 120 kHz | 833（約 9.7 bit） | 12 % | 0.76 |

- duty 下限：毎周期ローサイドを ON させ、ブートストラップを充電するため。上限は対称
- 3 脚のスライスは同じ設定で、同じクロックで同時に起動する（キャリア位相がそろう）。他のスライス（CH1/CH2）には触らない
- キャリアの変更は OFF / IDLE 中のみ。IDLE 中に変えたときは 3 脚を再起動して位相をそろえ直す

**変調波**（`invIsr()`）

```
θ      += step                       // step = f / fcAct × 2^32（32 bit 位相アキュムレーター）
v_U     = m × sin(θ)                 // sin は 1024 点 Q15 テーブル（上位 10 bit で参照、補間なし）
3P: v_V = m × sin(θ − 120°)、v_W = m × sin(θ + 120°)   // DIR=REV で V と W を入れ替え
1P: v_A = +m × sin(θ)、v_B = −m × sin(θ)、W = 0          // ユニポーラ
cc      = clamp(top1 × (1 + v) / 2, ccMin, ccMax)
```

- m は Q15（`isrM`）で割り込みに渡す。m・step・状態は `invPoll()` が更新する
- 電気角 θ は `invSetTheta()` / `invGetTheta()` で外から読み書きできる（ホール同期用の入口）

### 3.5 状態遷移

```
       ENABLE          10 ms 後
 OFF ─────────→ PRECHARGE ─────→ IDLE ←──────────────┐
  ↑   (SD=High, 全 IN=Low)       │ RUN / DC / AUDIO   │ m が 0 に到達
  │                              ↓                    │
  │                     RUN / DC / AUDIO ──STOP──→ RAMPDOWN
  │                                                   │ (DISABLE・USB 切断なら)
  └───────────────────────────────────────────────────┘
 どの状態でも 非常停止 → FAULT（SD=Low 保持）──ENABLE（スイッチ復帰後）──→ PRECHARGE
```

| 状態 | SD | 出力 | 入る条件 | 出る条件 |
|---|---|---|---|---|
| OFF | Low | 全 IN=Low（GPIO） | 起動、`DISABLE`、USB 切断後のランプ完了 | `ENABLE` |
| PRECHARGE | High | 全 IN=Low（全ローサイド ON） | `ENABLE` | 10 ms 後 IDLE |
| IDLE | High | m=0（全脚 50 %、出力 0 V） | プリチャージ完了、ランプ完了 | `RUN` / `DC` / `AUDIO START` |
| RUN | High | 正弦波 PWM | `INV RUN` | `STOP`・`DISABLE` → RAMPDOWN |
| DC | High | 固定角度の正弦波（step=0） | `INV DC` | タイムアウト・`STOP` → RAMPDOWN |
| AUDIO | High | 音声 PWM（1P） | `INV AUDIO START` | データ終了・`AUDIO STOP` → RAMPDOWN |
| RAMPDOWN | High | m を 2.0/s で 0 へ。**f は保持** | 上記 | m=0 で IDLE（`DISABLE`・切断なら OFF） |
| FAULT | Low | PWM 停止、全 IN=Low | 非常停止 | `ENABLE`（スイッチが戻っていること） |

- `DISABLE` は OFF / PRECHARGE / IDLE / FAULT なら即 OFF、運転中ならランプしてから OFF
- FAULT の要因は現在 `ESTOP` のみ

### 3.6 ランプ

| 対象 | 規則 |
|---|---|
| m | `M_RAMP_PER_S` = 2.0/s で目標へ（RUN / DC / AUDIO / RAMPDOWN） |
| f | `INV RUN` の加速度（既定 100 Hz/s、0.1〜100000 Hz/s）で目標へ。RUN 中のみ |
| 直流励磁の角度 | 90°/s で目標角へ |

要求仕様 3.3 の「下げるときは m が先、上げるときは f が先」の順序制御はない（m と f は同時に変化する）。

### 3.7 直流励磁（追加機能）

- `INV DC <deg> <m> [timeout]`：3P のみ。m ≤ 0.3、タイムアウト 1〜60 s（既定 10 s）
- IDLE から入ると角度はすぐ目標値になり、m が 0 から上がる。DC 中に角度を変えると 90°/s で移動する
- タイムアウトで `EVT INV DC TIMEOUT` を出してランプ停止
- DC から `INV RUN` を指令すると、f=0（そろえた角度）から加速する
- 用途：台車の磁石を決まった位置に引き付ける（同期モーターの位置合わせ）

### 3.8 オーディオ（単相）

**データの流れ**

1. アプリが音声ファイルを変換する（4.3）：モノラル、HPF 20 Hz、LPF（2 段）、ピーク 0.98 に正規化、16 bit PCM
2. `INV AUDIO START <fs> <bw> <m>` で AUDIO へ（再送すると音量 m だけ変更）
3. アプリがバイナリフレームで PCM を送り続ける（1 フレーム 1024 サンプル）
4. ファームウェアはリングバッファ（65536 サンプル = 128 KB）にため、キャリア周期ごとに `fs / fcAct` ずつ読み位置を進め、線形補間して出力する

| 項目 | 値 |
|---|---|
| fs | 4000〜48000 Hz（アプリは `fs = 2.5 × bw` を 4000〜48000 に丸める） |
| bw | 0 < bw ≤ fs/2、かつ **fc ≥ 8 × bw**（アプリは `bw = min(fc/8, 16 kHz)`） |
| 再生開始 | 2048 サンプルたまってから。データが 100 ms 止まれば、短いクリップもそのまま再生 |
| データ切れ | 無音にしてためなおす（`under` を加算） |
| 終了 | データが 1.5 s 来ず、バッファが空 → `EVT INV AUDIO END` → ランプして IDLE |
| 残量報告 | 50 ms ごとに `AUD fill=… free=… under=… drop=… bad=…`。送信バッファの空きが 80 byte 以上のときだけ |
| アプリの目標残量 | `min(fs × 1.0 s, 48000)` サンプル |

- USB の送信バッファは 256 byte しかない。再生中に送信待ちで止まると受信が遅れて音が切れるため、再生中に**定期的な `INV STATUS` の応答だけ**、送信バッファの空きが 128 byte 未満なら省略する。コマンドへの応答は必ず送る
- 3P では使えない（`ERR INV audio is 1P only`）

| 機能 | 実装 |
|---|---|
| 起動時 | `setup()` の最初で `invInit()`：SD=Low、全 IN=Low（USB 初期化より前） |
| リセット中 | SD はハイインピーダンス → 外付けプルダウンで Low |
| 非常停止 | GP11 立ち下がり割り込みで即 `hardStop()`（SD=Low が先、PWM 停止が後）。押しっぱなしも周期処理で検出。FAULT を保持し、押されている間は `ENABLE` を拒否 |
| USB 切断 | DTR が落ちたら m を 0 までランプして OFF。m の上限解除も取り消す |
| ウォッチドッグ | 500 ms |
| 起動手順 | 全 IN=Low（全ローサイド ON）で SD=High → 10 ms ブートストラップ充電 → 全脚 50 % |
| 指令のチェック | 範囲外・fc < 8×f1・m 上限超え・状態違いはすべて `ERR` で拒否（クリップしない） |
| m の上限 | 0.8。`INV LIMIT UNLOCK` で 0.99（USB 切断・再起動で 0.8 に戻る）。`NORMAL` に戻すと運転中の m もランプで下げる |
| duty 制限 | 3.4 の dmin（ブートストラップ充電とデッドタイム確保） |

### 3.10 通信プロトコル

USB CDC（115200 指定、実速度は USB に依存）。ASCII、1 行 1 コマンド、改行で終端。音声だけバイナリフレーム。

**インバーターのコマンド**

| コマンド | 受け付ける状態 | 内容 |
|---|---|---|
| `INV STATUS` | すべて | 状態行を返す |
| `INV MODE <3P\|1P>` | OFF | 3 相 / 単相 |
| `INV CARRIER <Hz>` | OFF / IDLE | 10000〜120000 |
| `INV ENABLE` | OFF / FAULT | プリチャージ付き有効化。非常停止中は拒否 |
| `INV DISABLE` | すべて | 無効化（運転中はランプしてから） |
| `INV RUN <f> <m> [accel]` | IDLE / RUN / DC | f 1〜1500 Hz、m 0〜上限、加速度 0.1〜100000 Hz/s。運転中に再送すると目標を変更 |
| `INV STOP` | RUN / DC / AUDIO | m→0 にして IDLE |
| `INV DIR <FWD\|REV>` | RUN / RAMPDOWN 以外 | 相順（V と W を入れ替え） |
| `INV LIMIT <NORMAL\|UNLOCK>` | すべて | m の上限 0.8 / 0.99 |
| `INV DC <deg> <m> [timeout s]` | IDLE / DC | 直流励磁（3P） |
| `INV AUDIO START <fs> <bw> <m>` | IDLE / AUDIO | 音声開始。AUDIO 中は音量変更 |
| `INV AUDIO STOP` | AUDIO | 音声停止 |

共通コマンド：`ID`（`OK ID FGEN-RP2040 v2 sys=200000000 inv=1`）、`STATUS`、`PWM …`、`WAVE …`（3.12）。

**音声バイナリフレーム**

```
0x02 0x5A len_lo len_hi <len バイト: int16 LE PCM> sum_lo sum_hi
```

- len：偶数、2〜4096 byte。sum：ペイロード各バイトの 16 bit 和
- 長さ不正・チェックサム不一致のフレームは捨てて `bad` を加算する
- フレームの途中で 1 s バイトが来なければ、テキスト受信に戻る
- 非表示文字を含むテキスト行（壊れたフレームの残り）は、エラーを返さずに捨てる

**応答**

| 種類 | 形式 |
|---|---|
| 状態行 | `OK INV state=RUN mode=3P fc=20000.0 top=5000 f=… ftgt=… m=… mtgt=… theta=… dir=FWD sd=1 fault=NONE estop=0 dmin=2.00 accel=100.0 mlim=0.80 abad=0` ＋ DC 中は `dcleft=`、音声中は `fs=` `bw=` |
| エラー | `ERR INV <理由>`（例：`carrier must be >= 8x fundamental`、`m out of range 0-0.80`、`not ready (enable first)`、`estop pressed`） |
| イベント | `EVT INV FAULT ESTOP`、`EVT INV DC TIMEOUT`、`EVT INV AUDIO END` |
| 音声残量 | `AUD fill=… free=… under=… drop=… bad=…` |

## 4. 操作アプリ（`web/`）

### 4.1 構成

| 項目 | 内容 |
|---|---|
| 形式 | ビルド不要の HTML / CSS / ES Modules。PWA（`manifest.webmanifest` の `id` = `/picofunc/`） |
| 公開 | GitHub Actions（`.github/workflows/pages.yml`）で `web/` を GitHub Pages に配信 |
| PC での起動 | `fgen_gui.bat` → `pc/launch_web.py` が `web/` を `http://127.0.0.1:8765/` で配信し、Chrome（なければ Edge）のアプリ窓で開く |
| USB | PC：Web Serial。Android：WebUSB で CDC-ACM を直接制御し、DTR を ON（`transport.js`） |
| 保存 | localStorage キー `fgen-ui-v1`（画面設定）、`fgen-inv-v1`（インバーター設定） |
| キャッシュ | Service Worker のキャッシュ名 `fgen-v11`。更新時は `fgen-` で始まる自分のキャッシュだけ消す |

### 4.2 インバーター操作カード（`web/js/inverter.js`）

- モード（3P / 1P）、キャリア、基本波 f、m、加速度、方向、直流励磁（角度・m・タイムアウト）、音声（ファイル・音量・ループ再生）
- ファームウェアと同じ制約（fc ≥ 8×f、m 上限、duty クリップ）を送信前に判定して表示する（計算は `sim.js` の `calcInverter()`）
- 状態の問い合わせ：運転・加減速中は 120 ms、それ以外は 300 ms ごとに `INV STATUS`
- 応答の合間は、ファームウェアと同じランプ規則で状態を予測して表示を滑らかにする
- 「上限解除」ボタン：確認ダイアログのあと `INV LIMIT UNLOCK`

### 4.3 音声の変換と送信

| 処理 | 内容 |
|---|---|
| 帯域 | `bw = min(fcAct / 8, 16000)` |
| サンプリング周波数 | `fs = round(clamp(2.5 × bw, 4000, 48000))` |
| フィルター | HPF 20 Hz（DC 除去）→ LPF 0.9×bw を 2 段（Web Audio の OfflineAudioContext） |
| 正規化 | ピークを 0.98 に合わせて int16 化 |
| 送信 | 10 ms ごとに、ボード内の推定残量が目標（`min(fs×1 s, 48000)`）を下回っていれば最大 8 フレーム送る |
| 開始の確認 | `INV AUDIO START` 後、`state=AUDIO` か `AUD` 行を受けてから送信開始。1 s で `INV STATUS` を再問い合わせ、3 s で中止してエラー表示 |
| キャリア変更時 | 帯域が 2 % 以上変わるなら再変換 |
| 画面更新 | 再生中は 10 回/s まで（受信・送信を遅らせないため） |

### 4.4 波形表示

オシロスコープ風の画面（自動測定、カーソル、FFT 65536 点）。**表示はファームウェアと同じ計算による模擬波形で、実測ではない**。接続中は実際の出力状態（OFF＝0 V、IDLE＝全脚 50 %）に合わせて描く。詳しい操作は README を参照。

## 5. 要求仕様との数値の相違

| 項目 | 要求仕様 | 現行 | 対応の方針（案） |
|---|---|---|---|
| fc 範囲 | 10〜150 kHz | 10〜120 kHz | 150 kHz は分解能約 9 bit・dmin 15 % になる。必要なら `FC_MAX` を変更 |
| IGBT 時の fc 上限 | 20 kHz | なし | `FC_MAX_IGBT` を追加し、`DRIVER_TYPE`／素子設定で切り替え |
| f1 範囲 | 1 Hz〜3 kHz | 1〜1500 Hz | `F1_MAX` を変更（fc 比の制約が実質の上限になる） |
| fc / f1 比 | ≥ 20 | ≥ 8 | `CARRIER_RATIO` を 20 に。音声の帯域（fc/8）も影響を受けるので、音声用の比は別定数に分ける |
| m > 0.8 | 0.8 にクリップ | 拒否（`ERR`） | 安全側の実装として現行のままでもよい。クリップにする場合は応答に実際の値を返す |
| m ランプ | 0.5 /s（パラメータ） | 2.0 /s（固定） | `RAMP_M_PER_S` として変数化 |
| f ランプ | 50 Hz/s（パラメータ） | 既定 100 Hz/s（コマンド引数） | `RAMP_F_HZ_PER_S` を既定値に |
| ランプの順序 | 減速は m 先、加速は f 先 | 同時 | V/f 制限と合わせて実装 |
| デッドタイム | 1000 ns（設定可） | IR2302 内蔵約 540 ns のみ | `HIN_LIN` 実装時に PWM で生成 |
| 音声 HPF | 30 Hz 程度 | 20 Hz | `inverter.js` の `hp.frequency` を 30 に |
| FAULT 解除 | `RESET` → IDLE | `INV ENABLE` → PRECHARGE | `RESET` コマンドを追加 |
| 停止 | STOPPING で減速、v=0 で READY | f を保持したまま m→0 | 走行用には f を下げながら止める STOPPING を追加 |
| 1 kHz 処理 | タイマー | メインループで 1 ms 経過ごと | ホール・区間処理を入れるなら `add_repeating_timer_us` などに移す |
| コマンド形式 | `MODE`・`FC`・`F1`・`M`… | `INV MODE`・`INV CARRIER`・`INV RUN f m`… | アプリとの互換のため `INV` 形式を残し、要求仕様の形式を別名として追加 |

## 6. 未実装機能と拡張方針（案）

### 6.1 着手順の提案

1. パラメータ化（`SET` / `GET`、5 章の値の変数化）と `RESET` コマンド
2. V/f 制限 `m_limit(f)` とランプ順序（要求仕様 3.3）
3. 過電流割り込み（`OC_FAULT_GPIO`）と FAULT 要因の追加
4. ホール入力・位置推定（3.4）→ `HALL_SYNC`（3.5）
5. 区間リレー（3.6）、ホーミング（3.8）
6. `HIN_LIN` 出力

### 6.2 実装の入口

| 機能 | 入れる場所 | メモ |
|---|---|---|
| `HIN_LIN` | `startPwm()`、`invIsr()` | U/V/W の slice 2/3/4 の B チャンネル（GP5/7/9）を LIN にする。B を反転（`pwm_set_output_polarity`）し、A と B の比較値をデッドタイム分ずらす。phase-correct では比較値の差 Δ カウントが、立ち上がり・立ち下がりの両エッジにそれぞれ Δ × 5 ns（200 MHz）ずつ入る（1000 ns なら Δ = 200） |
| ホール A/B/C・原点 | 新規 `hall.cpp`、GPIO 割り込み | エッジで位置 ±60°・時刻を記録。電気角は `invSetTheta()` で PWM 割り込みに渡す（割り込み内で補間するなら、step を速度から計算して `isrStep` に入れる） |
| 過電流 | GPIO 割り込みで `hardStop()` → FAULT | 非常停止と同じ経路。`faultReason` に要因を入れる |
| V/f 制限 | `invPoll()` の m ランプの後 | `mCur = min(mCur, m_limit(fCur))` |
| 区間リレー | 新規 `section.cpp`、`invPoll()` から呼ぶ | 16 区間なら GPIO 不足のため 74HC595 などのシフトレジスタ ＋ ULN2803。低速の無電流切り替えは SD=Low → `T_DECAY` → 切替 → 待ち → SD=High の状態機械にする（`invPoll()` の中で待たない） |
| 電流 ADC | GP26〜28 | 監視用。保護はハードウェアのコンパレーターに任せる |
| 状態の追加 | `enum State`、`STATE_NAMES`、アプリの `inverter.js` | アプリは状態名を文字列で判定しているので、名前を追加したら表示側も更新する |

### 6.3 互換性の注意

- アプリとファームウェアは、状態行の `key=value`、`EVT`／`AUD` 行、音声フレーム形式でつながっている。形式を変えるときは両方を同時に更新し、`sw.js` の VERSION を上げる
- `web/js/sim.js` の `INV` 定数と `calcInverter()` は `src/inverter.cpp` と同じ値・計算にしておく（表示と送信前チェックに使う）
